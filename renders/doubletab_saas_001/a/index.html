DoubleTab core
01 / Tasks service

Work objects, not tickets

A task is a first-class object with an owner, a thread, and a media bucket. Everything else in DoubleTab subscribes to it.

  • APIREST + WebSocket, fully documented
  • StorePostgres, append-only event log
  • Scale2.4M objects per workspace, tested
02 / Channel service

Threading that holds up

Collective channels and one-to-one messages share a single primitive, so a DM can become a thread without losing history.

  • CryptoEnd-to-end on direct messages
  • SearchFull-text across every thread you can see
  • SyncOffline-first clients, CRDT merge
03 / Media pipeline

Processed the moment it lands

Uploads fan out to a worker pool for transcode, transcript, OCR and thumbnailing, then return to the originating thread.

  • FormatsVideo, audio, image, PDF, CAD preview
  • Speed1080p hour-long recording in ~90s
  • CostRuns on your own object storage

02 / Automation

Direct communication,
on rails.

Four rule types cover most of what a distributed team asks a person to remember. Compose them in the builder, or commit them as YAML alongside your code.

Send the right update to the right thread based on board, label, owner or client. A handoff on one board becomes a message in three channels, with the media already attached.

Collect low-priority activity and deliver it once, at a time each person chooses. Nine notifications become one paragraph they'll actually read.

If a task stalls past its threshold, DoubleTab walks a defined ladder — thread, owner, then the next person on call — and stops the moment someone answers.

Every automated message respects the recipient's local hours by default. Urgency is a deliberate override, held in the audit log, not an accident of timezone.
